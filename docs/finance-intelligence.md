# 观潮：财经情报专业服务

`finance.watch` 是与“听风”独立的长期专业服务。成员“观潮”使用单独的人格、经历、偏好、候选池和扫描记录；它与 AI 情报只共享 SQLite、统一任务信封、Bark / Telegram 派发器和反馈机制。

这项服务整理公开信息，不构成投资建议。输出只允许描述已知事实、可能的影响路径和下一观察点，不得给出买卖、持有、目标价、仓位或收益建议。

## 信息源分层

| 等级 | 作用 | 一期来源 | 使用边界 |
| --- | --- | --- | --- |
| S0 | 法定披露、监管原文 | 巨潮资讯、证监会、SEC EDGAR | 关键事实的首要证据 |
| S1 | 官方宏观和央行发布 | 人民银行、国家统计局、美联储、香港金管局；FRED、BLS、BEA 候选 | 宏观事件、数值复核和历史修订 |
| S2 | 授权专业新闻 | Reuters、Bloomberg 等候选 | 只有正式许可接口才启用 |
| S3 | 结构化行情与事件发现 | Tushare、Wind 等候选 | 用于发现和量化，不替代原文 |
| S4 | 社交和社区信号 | 后续候选 | 只发现线索，不独立触发高置信推送 |

一期默认启用无需密钥且适合服务器采集的官方来源。上交所、深交所、北交所作为权威回查入口，由巨潮公告速递承担统一发现；HKEX IIS、FRED、BLS、BEA、Tushare、Wind、Reuters 和 Bloomberg 进入可观察的来源目录，但在具备合规适配器、凭据或商业授权前不会伪装成已接入。

每个来源都有独立健康状态、最近成功时间、条目数和 48 小时缓存。单个来源失败不会阻断其他来源；使用缓存时会显式标记，不能把旧数据伪装成实时数据。

## 候选门禁

观潮先让模型合并同一事件并评分，随后再由确定性代码执行：

1. 采集逐跳限制在登记来源的 HTTPS 同源地址，正文按字节流限制大小；RSS、Atom 和页面条目中的越界链接直接丢弃。
2. 模型 URL 必须逐字来自本轮来源证据，且标题、摘要、正文和理由不得包含买卖、目标价、仓位或收益行动建议；越界会要求模型修正一次，再失败则整轮拒绝。
3. 自选标的命中会增加兴趣，但不会绕过可信度和重复门禁。
4. 非自选公司事件只有在重大披露或高重要性时才允许进入推送队列。
5. 监管、货币政策和关键宏观事件可作为广域事件进入候选池。
6. AI 与财经的重复历史、推送节流和反馈权重按 `domain` 隔离。

Web 的“双域情报台”可配置：关注方向、CN / HK / US 市场、自选清单、来源类别、扫描间隔、推送间隔和阈值。自选清单每行格式为：

```text
CN:600519 贵州茅台
HK:00700 腾讯
US:NVDA NVIDIA
```

## MCP 委任

外部 AI 不需要选择模型或拼装来源。它只创建一次长期任务并轮询结果：

- `totemora_list_finance_briefs`
- `totemora_list_finance_candidates`
- `totemora_list_finance_sources`
- `totemora_run_finance_watch`
- `totemora_get_finance_task`

Chief 根据 `finance.watch` 的长期绑定委任观潮；来源采集、模型评估、确定性门禁、候选派发和经历记录都留在 Gateway。
相同领域与 `idempotency_key` 会返回已有任务，不会重复安排扫描或外发。

## 运行与验证

```bash
TOTEMORA_HOST=0.0.0.0 bun run dev:web
```

打开 `http://<服务器局域网 IP>:4310`，输入操作员 Token，在“观潮 · 财经情报”中保存范围并点击“让观潮立即扫描”。来源账本应显示本轮成功或降级原因；候选卡应带有 S0 / S1、市场、代码和事件类型；Bark 状态只显示目标 ID，不显示 device key。

后续增加信息源时，先把它登记为来源目录项并说明证据等级、许可方式、市场、用途和降级策略；只有实际适配和测试通过后才改为 `active`。
