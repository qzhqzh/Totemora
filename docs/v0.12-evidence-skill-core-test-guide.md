## Git Skill 对照试炼

1. 在“能力议事”委任 `git-change-management` 的一项改进，目标成员选择 `deepseek_git_steward`，目标服务选择 `git.flow`。
2. 草案形成后点击“校验并进入试用”，记录案卷 ID。
3. 在任务大厅选择有未提交改动且已安装 Policy 的 Git 工作地，保持“试用中的 Skill Commission ID”为空，运行一次相同目标；记下专业任务 ID。
4. 不修改工作树，把案卷 ID 填入该字段并重跑；第二份 Proposal 的 `skill.commission_id` 应等于案卷 ID，digest 与基线不同。
5. 把两份专业任务 ID 登记为一次试炼。Reviewer 必须与任务中实际 Chief 一致，Token、时延与验收由服务端读取，页面不允许手填。
6. 重复三个独立任务后，“提议正式装备”才可用；批准前普通任务不能加载候选包，批准后会加载，回滚后又停止加载。

试炼只形成 Git 计划与 Chief 验收；不要批准后续 Commit / PR 门禁，除非你确实希望产生对应 Git 副作用。

## 十任务收益实验

```bash
bun run totemora benchmark run \
  --suite benchmarks/core-proof-v1.json \
  --strong-member deepseek_reasoner \
  --cheap-member qwen_worker \
  --chief deepseek_reasoner \
  --config-dir configs/example \
  --data-dir .totemora
```

该命令会产生至少 30 次真实模型调用。没有经过核验的价格快照时不要传 `--pricing-snapshot`；结果应明确显示 `unconfigured`，而不是 `$0`。

## 当前不在验收范围

- Telegram 中创建或继续 Commission；
- 自动执行第三方 Skill 脚本；
- 非 Git 专业服务的隔离试用适配器；
- 仅凭十个同一业务样本证明部落具有跨领域收益。
