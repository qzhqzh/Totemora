# ADR-0022：项目情报的类型化决策与每日精选

状态：Accepted。

## 问题

听风已经采集证据并生成候选，但通用兴趣分数不能充分表达当前项目的需要。模型打分、事实可信度与通知时机也需要分别保存和验证。

## 决策

- Core 提供独立的 `DecisionProvider` 契约，Providers 中的 Jev 适配器只处理类型化模型调用；原有 `AgentProvider.generate` 保持兼容。Jev 不负责授权、状态机或通知。
- Gateway 拥有项目卡、评估、预算和精选状态。首版只处理 AI 域，默认 `off`；`shadow` 每小时评估但沿用原通知行为；`active` 将普通听风候选留待每日精选。财经晨报保持原契约。首版 `immediate` 是优先级建议，仍随每日精选发送。
- 原始采集证据、有限历史与显式项目卡构成评估上下文。缺少原文进入 `review`；不读取其他项目文件或聊天。模型输出只能形成建议，不能提高既有事实可信度、提升 `held` 候选或扩展资产授权。
- 每天按条数与输入 token 预算原子预留；成功按实际用量结算，失败保守记账。相同输入同日防重复收费。缓存包含问题版本、模型、配置、证据、历史和日期。
- Migration 017 追加配置、评估和预算表；018 追加摘要、条目保留与调度状态。旧 migration 和候选数据保留。摘要与旧派发器共享候选状态，摘要条目不能再被普通派发器领取。
- 摘要先保存固定消息快照并领取带 fencing token 的发送权，再经已有 Notifier 投递。明确失败最多三次，以原消息、原幂等键重试；`uncertain` 和过期 `sending` 不自动重放。通道接受不等于用户阅读。
- Jev 不可用、失败或预算不足时普通情报回退到旧链路。接入和观察通过 Operator 配置开启；读取项目卡和评估也需要鉴权。

## 验证与限制

离线测试覆盖模型响应边界、预算竞争、缓存变化、缺失证据、旧数据库升级、摘要并发/重试/未知状态和真实浏览器交互。模型质量、真实成本、凭据连通性及实际投递需要后续小范围观察验证。

当前实现复用原候选摘要生成精选正文，不额外生成项目建议段落。项目相关性通过项目名、评分及本地规则原因展示。后续可在来源引用契约内加入生成摘要，须单独验证准确性。
