# ADR-0007：成员生命、谱系与营帐对话

- 状态：Accepted
- 日期：2026-07-14

## 决策

成员是有连续身份的实体，不是一次模型调用的别名：

```text
Member = Ember + Persona + Skills + Asset Grants + Lineage + Experience + Trust + Version
```

每名成员可以声明导师、专业谱系、辈分、出生时间、复验周期和能力证据衰减半衰期。成员档案同时保留成功、失败、求助、导师指点和普通交流；只有有来源且 `verified=true` 的经历能提高已验证能力。

成员私聊必须带入其人格、谱系、成长状态与最近经历。弱成员可以显式向同谱系导师求助：系统保存 `help_request` 和 `mentor_guidance`，导师只给框架与提醒，最终仍由原成员用自己的身份回答。

## 成长与衰老

- 成长不等于静默改 Prompt。真实成功累计到复验阈值后，只产生可审核的成长资格。
- 长期没有新的已验证经历时，`vitality` 按配置半衰期下降；历史不删除，但旧证据权重降低。
- 模型、Skill 或成员版本变化后需要复验，不能无条件继承全部信任。
- 退休成员保留生平和经历，但不再参与派工或对话。

## 当前实现

`MemberStateStore` 聚合成员配置、已验证专员经历和营帐记忆；`MemberConversationService` 提供持久私聊和导师求助。Web“成员营帐”和 MCP 成员工具共享同一状态。

当前只计算成长资格，不自动晋级或改 Persona。下一阶段增加成长提案审批、能力按任务类型的复验和成员关系图。
