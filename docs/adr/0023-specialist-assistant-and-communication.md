# ADR-0023：常驻专业助手与多渠道消息沟通

- 状态：Accepted
- 日期：2026-10-25
- Supersedes：ADR-0001 的产品重点与交付顺序；保留其预算、证据及收益验证要求。补充 ADR-0022 的规则基线与行动采纳边界。

## 背景

生态中的 EchoMe 已承担记忆与上下文，Lifeline 承担项目排期与验收，LogWood 承担提示词、评测和内容沉淀。Totemora 已有专业任务、情报、通知与反馈内核，但通用多模型组织收益尚无充分实测。用户明确要求将服务收敛为常驻专业助手，同时负责多种方式的消息沟通与传递。

## 决策

1. 首个业务闭环是项目情报 → 有原始来源的行动建议 → 采纳/忽略 → 明确标记的外部任务交接。首版交接仅生成 Lifeline 草稿；没有真实项目/阶段映射与调用回执时，不能声称创建任务。
2. 多渠道沟通是产品核心。Gateway 持有业务判断、授权和用户决定；同仓独立 Notifier 持有 Bark、ntfy、Telegram、邮件的投递契约和账本。Web、Telegram 的交互使用同一业务状态。通道支持、配置成功、通道接受、用户阅读和行动采纳必须分别表达。
3. 无 Jev 时使用有界、可解释的字面规则匹配：匹配对应采集材料中的项目关注词，排除项优先，保留既有事实、新颖度和发送门槛。规则不伪造模型概率或紧急性，`decision_confidence=null`，不消耗模型 Token。Jev 保留为可选决策 Provider。
4. 行动建议单独持久化，保留来源快照；采纳不自动授予模型、Shell、Git、发布或通知权限。重复决定必须幂等，相反决定冲突。正式项目排期与验收仍归 Lifeline。
5. 外部来源失效进入可检查的受阻/退避状态，跨重启保留原因和下次探测时间。不得绕过访问验证、关闭 TLS 校验，或把跳过请求显示为源已恢复。
6. 成员、Skill、预算和验收作为内部能力保留。人格成长、通用编排扩张及更多资讯频道后置，以真实采纳与可验证结果决定投入。

## 验证

覆盖无密钥评估、缺来源和排除项、原发送门槛、同候选去重、采纳状态与 migration 19、幂等冲突、旧数据保留、Telegram 白名单和未知发送结果不重放；桌面与手机验证设置、反馈、交接和退出清理。

离线通过仅证明实现链路。来源恢复、真实通道外发、Lifeline 提交和实际有用性各自需要独立证据。当前库存与部署前提见[服务重启清单](../service-relaunch.md)。
