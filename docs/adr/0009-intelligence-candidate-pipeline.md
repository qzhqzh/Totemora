# ADR-0009：情报候选池与节流派发

- 状态：Accepted
- 日期：2026-07-20

## 背景

小时级“扫描后立即批量推送”会同时放大模型延迟、来源波动和重复消息。扫描频率、消息价值判断与外发频率不是同一个问题，必须分开治理。

## 决策

情报链路拆成三个独立阶段：

1. 常驻 Gateway 每分钟 Tick，默认每 10 分钟领取一个扫描窗口。
2. 听风收集白名单来源，聚合同一事件并给出重要性、兴趣匹配、可信度、新颖度和推送价值；系统再执行固定阈值、URL/事件键/标题相似度去重等确定性门禁。
3. 通过门禁的消息进入候选池，派发器按总分选择下一条，默认至少间隔 60 秒才向 Bark 外发一条。

候选状态为 `queued`、`held`、`pushing`、`pushed`、`failed` 和 `delivery_unknown`。同一事件只有模型明确标记为更新且新颖度足够高时才能再次入队。服务在外发确认前中断时，不自动重推，而是标记 `delivery_unknown` 交给人检查，优先避免重复打扰。

没有 Bark 凭据、某次 Bark 失败或候选池暂时为空，都不能阻止后续扫描。外发故障记录为系统故障，不计入成员能力失败。

## 边界

当前候选池是单 Gateway 的本地持久文件和进程内串行事务，适合个人服务器常驻节点。扩展为多副本或多进程派发前，必须迁移到带事务和租约的共享存储；不能让多个实例同时消费同一候选。
