# ADR-0014：双人协作内容工坊与发布边界

- 状态：Accepted
- 日期：2026-08-10

## 背景

听风台已经能把 RSS、AI HOT、X 与微博等来源整理为带可信度、兴趣和新颖度证据的候选池，但“发现值得关注的消息”与“形成可对外使用的内容”是两件不同的工作。若直接让单个模型根据热点写稿，容易丢失来源、扩大事实或让所谓成员协作退化为同一输出换几个名字。

## 决策

新增 `content.studio` 长期专业服务，提供两种作品：

- `x_hot_post`：不超过 280 个 Unicode 字符、保留来源 URL、可直接复制的单条 X 热点短帖。
- `longform_tutorial`：围绕热点形成的教程或经验总结，区分来源事实、实践推导和待验证项。

每份内容至少有两名不同成员实际参与：

```text
Chief 常驻委任
  -> 听风：选题研究与事实边界
  -> 千工：目标渠道写作
  -> 听风：独立审校
  -> 确定性校验：来源、长度、协作人数
  -> 可复制案卷
```

Chief 对重复、低风险内容使用可解释的常驻委任，不为每一篇稿件额外消耗一次强模型调用。每次研究、写作、返修和审校都写入作品贡献记录；少于两名不同成员的作品不能进入 `ready`。

## 成长证据

- 生成或协作审校通过只记为 `operation`，不增加经验信用。
- 用户成功复制作品视为一次明确采纳信号；首次复制为每名参与成员记录 `0.5` 份 `user_feedback` 信用。
- 后续真正发布后的平台回执与质量反馈应成为更强证据，但不能仅凭“API 返回 201”判断内容质量。

## 不定时创作

用户可在 Web 中启用创作节律并设置最短、最长小时数。服务为下一次运行生成区间内的随机时间，先持久化下一窗口再开始模型工作，避免进程并发重复触发；同一情报候选默认不会重复用于自动创作。默认关闭，避免未经用户同意持续消耗 Token。

## 自动发布边界

当前版本只提供“复制正文”，不保存社交平台发布凭据，也不自动对外发布。

未来发布必须作为独立适配器与门禁实现：

```text
ready work
  -> operator approval
  -> publication adapter (x / long-form platform)
  -> idempotency key = work + target + revision
  -> external receipt (remote id, URL, time)
  -> optional engagement feedback
```

X 官方接口使用 `POST /2/tweets`，发布需要用户上下文授权而不是只读 App Bearer Token。凭据必须继续放在环境变量或本地 secret 文件中，最小权限、不可进入作品记录。长文平台在用户选定目标前只保留 `PublisherAdapter` 契约，不提前绑定某个产品。

## 后果

- 内容作品成为可持久化、可筛选和可追溯的部落成果，而不是聊天文本。
- 候选池负责发现，内容工坊负责生产，未来发布适配器负责外部副作用；三个边界彼此独立。
- 双人协作增加两到三次模型调用，换来来源研究和独立审校证据；Chief 常驻委任用于控制强模型预算。

## 验证

- X 短帖和长文分别通过服务测试。
- 每份 `ready` 作品有至少两名不同成员贡献。
- Gateway 创建接口返回后台任务，作品状态可轮询并在重启中断后安全失败。
- Web 能配置不定时创作、筛选作品，并在 HTTPS 与局域网 HTTP 下复制正文。
