# ADR-0017：独立财经情报垂直与按领域通知路由

状态：Accepted

## 背景

听风已能处理 AI 新闻、技术 RSS 和社交热点，但财经信息的证据责任不同：法定披露、监管原文和宏观发布时间比热点热度更重要；同一标题可能涉及不同市场与证券；错误数字或暗示买卖的代价也更高。把财经关键词直接追加到听风会混合人格、来源质量、反馈历史和推送阈值，无法判断成员是否真的形成了专业能力。

另一个现实需求是多台手机。通知目的地不能继续等同于一个全局 device key；不同设备可能只关心 AI、财经或两者，单台故障也不应熔断所有目标。

## 决策

1. 新增长期专业服务 `finance.watch` 和成员“观潮”，复用统一 `SpecialistTask`、成员经历、资产授权和 Gateway，不创建第二套 Runtime。
2. 候选对象增加 `domain`、`market`、`symbols`、`source_id`、`event_type` 和 `evidence_tier`；旧数据迁移后默认为 `ai`。
3. 财经偏好、来源健康、扫描租约和简报使用独立命名空间。重复抑制、反馈学习和推送选择按领域隔离。
4. 来源采用 S0–S4 证据分层。官方与法定披露优先；商业或需凭据的来源先进入可观察目录，未接入不得标为可用。
5. 模型负责事件合并、摘要和初始评分；确定性代码负责采集同源/大小边界、URL 白名单、投资行动建议拦截、自选匹配、重大性、证据下限、去重和节流。固定晨报的外发正文只使用确定性行情快照，不直接拼接模型自由生成的数字或归因。URL 或投资建议越界只允许一次受限纠正，再失败则整轮拒绝。
6. Bark 从单 key 兼容升级为多个目标。每个目标包含稳定 ID、服务器 URL、领域列表和启用状态；设备密钥只存在 Secret 或环境变量中。熔断、幂等动作和健康状态按目标隔离。
7. Web 在同一情报控制面展示 AI 与财经两个工作区；MCP 暴露结果导向的财经扫描、查询和来源账本工具。

## 未选择

- 不把财经关键词并入听风：会混合来源标准、画像与反馈。
- 不让模型直接浏览任意网址：难以保证来源、许可、超时与 SSRF 边界。
- 不先接行情交易终端：一期目标是高质量事件情报，不是实时行情、量化策略或下单系统。
- 不为每台 Bark 设备复制候选队列：统一候选只按目标记录幂等动作，部分失败可单独重试。

## 结果

财经服务能独立成长和复盘，也能共享部落的稳定基础设施。代价是增加了领域字段、来源适配器和配置面；来源页面结构变化仍可能导致降级，因此必须保留健康账本、缓存和回归样本。任何未来的实时行情、付费新闻或交易能力都需要新的许可、安全和延迟语义决策，不能由本 ADR 自动授权。
