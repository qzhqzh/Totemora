# v0.6 常驻部落验收指南

本节点验证四件事：成员有可追溯生命档案；成员能带着经历私聊并向导师求助；情报员能作为小时级常驻任务运行；外部 AI 能通过 MCP 创建持久任务并稍后查询结果。

## 1. 启动驻扎地

```bash
cd /home/zhuqin/star/app/Totemora
TOTEMORA_HOST=0.0.0.0 bun run dev:web
```

打开 `http://<服务器局域网 IP>:4310`。如果只在本机测试，使用 `http://127.0.0.1:4310`。

首次启动会生成 `.totemora/operator-token`。Bark 凭据只放在本机秘密文件中，不写入 agents 配置、资产卡或 Git：

```bash
mkdir -p .totemora/secrets
chmod 700 .totemora/secrets
${EDITOR:-vi} .totemora/secrets/bark-url
chmod 600 .totemora/secrets/bark-url
```

秘密文件内容为完整 Bark 基础地址。服务只接受 `https://api.day.app`。

## 2. Web 验收

1. 在“成员营帐”选择“听风 · 情报员”，确认可看到谱系、导师、年龄、活力、成功、失败、求助和指点记录。
2. 输入一个情报复盘问题，勾选“请他向同谱系导师求助后再回答”。预期会依次出现用户消息、求助、导师指点和听风自己的回答。
3. 在“听风台”点击立即巡查。页面应快速拿到持久任务，模型继续在后台工作；稍后刷新历史可看到结果、来源警告和推送数量。

## 3. MCP 验收

先导出服务端生成的 operator token，再按 [mcp-gateway.md](mcp-gateway.md) 配置 HTTP MCP：

```bash
export TOTEMORA_OPERATOR_TOKEN="$(tr -d '\n' < /home/zhuqin/star/app/Totemora/.totemora/operator-token)"
```

让调用方 AI 按顺序执行：

```text
1. 调用 totemora_list_members，找到听风并读取它的成长档案。
2. 调用 totemora_run_intelligence_brief，message_count 设为 2。
3. 保存返回的 task_id；不要因模型耗时重复创建任务。
4. 调用 totemora_get_intelligence_task 轮询到 completed 或 failed。
5. 调用 totemora_list_actions，核对每条 Bark 动作都有唯一幂等键和 completed 证据。
```

`totemora_run_intelligence_brief` 返回的是持久任务，不要求 MCP 连接一直等待 Qwen。服务重启后，尚未完成的任务会标记为失败并允许调用方显式重试，不会静默重复外发。

## 4. 小时调度与边界

- 服务每分钟检查一次是否到期，但每小时最多产生一份情报。
- 单个 RSS 失败只形成 warning；所有来源都失败时任务失败。
- 来源主机、响应体大小、请求超时和跳转都有硬限制。
- 模型输出里的 URL 必须逐字来自本轮采集证据；首次越界会获得一次受限纠错机会，再次越界则任务失败且不外发。
- Bark 调用经过幂等动作日志，密钥不进入模型上下文和动作日志。
- 当前边界是单进程本地服务，不等同于容器或操作系统级沙箱；接入任意 Shell 资产时仍需独立的命令、路径和网络策略。
