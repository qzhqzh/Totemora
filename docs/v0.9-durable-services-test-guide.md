# v0.9 持久专业服务验收

## 启动

```bash
docker compose -f compose.bark.yaml up -d
curl http://127.0.0.1:18080/info

bun run storage:migrate
bun run storage:verify

TOTEMORA_HOST=0.0.0.0 bun run dev:web
```

打开 `http://<服务器局域网 IP>:4310`，从 `.totemora/operator-token` 复制操作员
Token 到页面右上角。

## Bark

1. 按 [internal-bark.md](internal-bark.md) 让 Bark App 在自建服务器注册；
2. 把新 device key 写入 `.totemora/secrets/bark-device-key`；
3. 无需重启 Gateway；device key 会在下一次健康检查或推送时重新读取；
4. 页面“内部 Bark”应显示在线，`/info` 的 `devices` 应大于 0；
5. 立即扫描后观察候选从 `queued` 到 `pushed`。Bark 不可用时，应看到
   `retry_wait` 或 `channel_blocked`，扫描本身仍继续。

## 反馈与成长

- 对候选分别点击“有价值、没价值、重复、太晚”，按钮应显示进行中、成功或可重试错误；
- 相同反馈重复提交不重复计权；
- 下一条相似候选显示模型原始分、反馈校正和最终分；
- 配置 `TOTEMORA_PUBLIC_BASE_URL` 后，从 Bark 打开消息应记录一次 `opened`；
- 听风的日常扫描只增加“日常操作”，不增加经验信用；
- “有价值”增加 1 份信用，Bark 打开增加 0.2 份信用；
- 满 10 份新信用且过 7 天冷却后才可生成成长提案；
- 批准后人物营帐显示 vN → vN+1、具体变更字段，以及后续 10 份信用的观察状态。

## 专业服务

```bash
curl http://127.0.0.1:4310/api/services | jq
```

应看到：

- `git.flow` 绑定 `deepseek_git_steward`；
- `intelligence.watch` 绑定 `qwen_intelligence`；
- 每个服务只有白名单 operation，没有任意 prompt 执行入口。

MCP 发现应包含 `totemora_list_services` 和统一只读的 `totemora_get_task`，同时保留
Git Flow 与情报的强类型启动工具。
