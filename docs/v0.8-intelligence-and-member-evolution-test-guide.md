# v0.8 候选情报与成员演化验收指南

本节点验证两条闭环：听风高频扫描但克制推送；成员从任务证据形成画像，并通过导师提案和审批产生新版本。

## 1. 启动

```bash
cd /home/zhuqin/star/app/Totemora
TOTEMORA_HOST=0.0.0.0 bun run dev:web
```

> 历史验收指南。当前节点与内部 Bark 请分别使用
> [ADR-0011](adr/0011-durable-specialist-service-kernel.md) 和
> [internal-bark.md](internal-bark.md)。

本机访问 `http://127.0.0.1:4310`，局域网使用 `http://<服务器 IP>:4310`。
Bark device key 放在 `.totemora/secrets/bark-device-key`。

## 2. Web 验收情报链路

1. 打开“听风台”，保存扫描间隔 `10` 分钟、推送间隔 `60` 秒、推送阈值 `0.72` 和关注方向。
2. 点击“立即扫描候选池”。按钮创建持久后台任务，不会直接批量推送。
3. 任务完成后检查候选卡：应显示四项分数、总分、模型理由和系统门禁决定。
4. `queued` 会由常驻派发器处理；消息较多时也只能每分钟一条。`held` 表示低价值或重复，`delivery_unknown` 表示服务中断导致外发结果无法确认且不会自动重推。
5. 再扫描同一批来源，雷同事件应进入 `held`；只有带新事实且高新颖度的更新才能再次进入队列。

## 3. Web 验收成员画像

在“成员营帐”选择听风，检查：

- 正式性格内核及版本；
- 观察画像和置信度；
- 完成、验收成功、成员失败、系统失败与成功率；
- 首次成功、累计成功、导师指点和画像升级等重大经历；
- 待审成长提案。

听风每累计 10 次新的已验证成功会自动请导师生成成长提案。批准前画像版本和实际提示词不变；导师或 Chief 批准后版本加一。原则、红线、权限和模型不在可演化范围。

成长门禁可用针对性测试快速验证：

```bash
bun test packages/server/src/member-profile-store.test.ts packages/server/src/member-evolution-service.test.ts
```

## 4. MCP 验收

```bash
export TOTEMORA_OPERATOR_TOKEN="$(tr -d '\n' < .totemora/operator-token)"
```

让外部 AI 调用：

```text
1. totemora_run_intelligence_brief(delivery_mode="candidate_pool")
2. 用 task_id 轮询 totemora_get_intelligence_task
3. totemora_list_intelligence_candidates 检查评分、去重和队列状态
4. totemora_get_member(member_id="qwen_intelligence") 检查画像、履历和重大经历
```

`direct_push` 只保留给显式兼容测试；日常任务应使用默认 `candidate_pool`。
